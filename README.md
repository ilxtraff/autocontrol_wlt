# Автоконтроль адсетов

Выключает адсеты Facebook, вышедшие за пороги, **считая статистику из Keitaro**, и
следит за выключенными ещё три часа: вернулись метрики — включает обратно.

Параметры разделения и выключения повторяют автоконтроль из ATLANTIX CRM:
те же три правила, те же общие и личные пороги по гео, тот же журнал решений.

---

## Что делает движок

Каждые 10 минут (настраивается) для каждого адсета под контролем:

1. строится окно суток **от 00:00 по таймзоне рекламного кабинета**;
2. это окно пересчитывается в пояс трекера и одним запросом уходит в Keitaro;
3. метрики сравниваются с порогами адсета.

| Состояние | Что значит | Что делает движок |
|---|---|---|
| `НАБЛЮДАЕТ` | адсет работает | превышен порог → выключает адсет в Facebook |
| `ВЫКЛЮЧИЛ · правило` | выключен движком, идут 3 часа наблюдения | метрики вернулись в норму → включает обратно |
| `СНЯТ` | 3 часа прошли, метрики не вернулись | больше не трогает, адсет остаётся выключенным — включить может только человек |
| `БЕЗ КОНТРОЛЯ` | снят кнопкой «снять» | ничего; статус адсета в Facebook не менялся |

Если выключенный адсет снова оказался активен в Facebook, движок это замечает,
пишет в журнал «включил человек» и возвращает адсет под наблюдение.

### Правила

Проверяются в порядке **CPA → расход без конверсий → uCPC**; в журнал попадает
первое сработавшее. Пустой порог означает, что правило выключено.

| Правило | Формула | Когда применяется |
|---|---|---|
| CPA | `расход / конверсии` | есть хотя бы одна конверсия |
| расход без конверсий | `расход` | конверсий ещё нет |
| uCPC | `расход / уникальные клики` | есть хотя бы один уникальный клик |

Порог — это строго «больше»: `$5.00` при пороге `$5.00` не выключает.

Как только долетает первая конверсия, правило расхода уступает место CPA — поэтому
адсет с расходом `$14.90` при пороге `$5.00` продолжает работать, если его CPA
укладывается в лимит.

### Три часа наблюдения

После выключения адсет перепроверяется **по дню своей остановки**, а не по
текущему: долетевший лид меняет CPA именно тех суток. Если за три часа метрики
вернулись в норму — адсет включается обратно; если нет — контроль снимается, и
адсет остаётся выключенным.

### Часовые пояса

Keitaro работает по Москве, рекламные кабинеты — чаще всего по американскому
времени. Контроль идёт **от 00:00 по таймзоне кабинета**: движок берёт полночь в
поясе кабинета, переводит её в абсолютное время и отправляет в Keitaro уже как
московское.

Кабинет в Лос-Анджелесе, 14 сентября:

```
00:00 America/Los_Angeles  =  10:00 Europe/Moscow
запрос в Keitaro: from 2026-09-14 10:00:00, to <сейчас>, timezone Europe/Moscow
```

Переход на летнее/зимнее время учитывается — в такие сутки окно становится
23- или 25-часовым.

### Пороги

Два уровня, как в CRM:

* **Общие пороги по гео** — правила команды. Видят все, меняют только `admin` и
  `group CEO`.
* **Мои пороги** — личный список. Перебивает общий дефолт по этому гео. Вести
  весь список необязательно: держите здесь только гео, где числа отличаются.

Пороги **копируются в адсет в момент постановки под контроль**. Правка справочника
влияет на новые заливы, а идущие доживают по своим числам.

## Установка

Пошаговая инструкция с нуля — в [НАСТРОЙКА.md](НАСТРОЙКА.md). Коротко:

```bash
pip install -r requirements.txt
cp .env.example .env          # и поправьте AC_SECRET_KEY
python -m app.cli createuser admin --role admin
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000/` — попадёте на форму входа.

Движок по умолчанию крутится внутри веб-процесса. Чтобы вынести его отдельно,
поставьте `AC_RUN_ENGINE_IN_WEB=false` и запустите:

```bash
python -m app.engine
```

### Подключение

На странице **Интеграции**:

1. **Keitaro** — адрес трекера, API-ключ, таймзона (`Europe/Moscow`) и поле, в
   котором лежит ID адсета (`sub_id_6`, если параметр `adset_id` замаплен туда).
2. **Социальный аккаунт Facebook** — мультитокен: токен, куки, прокси и
   user-agent одной вставкой. Запросы идут через прокси аккаунта, а куки
   позволяют перевыпустить протухший токен без участия человека. Создавать
   приложение на developers.facebook.com не нужно. Проверить —
   `python -m app.cli fb-accounts`.
3. **Рекламный кабинет** — ID, токен и трекер. Таймзону можно не указывать:
   она подтянется из Facebook по токену, а именно от неё считаются сутки.

### Что нужно проверить в Keitaro

Движок читает расход из колонки `cost`. Keitaro знает о расходе Facebook только
если он в неё передаётся — через передачу цены клика в ссылке
(`&cost={{adset.bid_amount}}` и подобное) или через интеграцию с кабинетом. Если
расход в трекер не попадает, правила CPA и «расход без конверсий» работать не
будут: движок увидит нули и никого не выключит.

Так же важно, чтобы ID адсета доходил до трекера. В ссылке должен быть
`adset_id={{adset.id}}`, а в настройках сервиса — тот sub_id, на который этот
параметр замаплен в Keitaro (**Настройки → Параметры**). Номер у всех разный, и
ошибиться легко: движок просто увидит нули. Если не уверены —
`python -m app.cli find-field --account <ID>` переберёт sub_id 1..15 и скажет,
в каком лежат ID адсетов; `doctor` проверяет это сам и предлагает верное поле.

### Переменные окружения

Все настройки — в `.env.example`. Самые важные:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `AC_SECRET_KEY` | — | подпись сессионных кук, обязательно задать |
| `AC_TICK_SECONDS` | `600` | как часто движок делает проход |
| `AC_RECOVERY_HOURS` | `3` | сколько следим за выключенным адсетом |
| `AC_KEITARO_TIMEZONE` | `Europe/Moscow` | пояс трекера |
| `AC_KEITARO_ADSET_FIELD` | `sub_id_6` | поле с ID адсета |
| `AC_DRY_RUN` | `false` | считать и писать журнал, но ничего не выключать |

`AC_SECRET_KEY` шифрует мультитокены в базе — менять его нельзя, иначе
сохранённые секреты станут нечитаемы.

`AC_DRY_RUN=true` — хороший способ посмотреть на решения движка, прежде чем дать
ему трогать боевые адсеты.

## Команды

```bash
python -m app.cli createuser sasha --role buyer   # роли: buyer, admin, ceo
python -m app.cli passwd sasha
python -m app.cli users
python -m app.cli doctor      # проверить интеграции и что реально видит Keitaro
python -m app.cli social-add "Камилла"          # аккаунт из мультитокена
python -m app.cli import-accounts               # завести кабинеты токена пачкой
python -m app.cli find-field --account 123      # подобрать sub_id с ID адсетов
python -m app.cli fb-accounts # кабинеты, доступные токену
python -m app.cli import-adsets --account 123  # поставить адсеты кабинета под контроль
python -m app.cli tick        # один проход движка вручную
```

## Тесты

```bash
python -m pytest -q
```

Покрыты правила порогов (на реальных строках из журнала CRM), расчёт суток по
поясу кабинета с переходом на летнее время, запрос в Keitaro, весь цикл движка
(выключение → возврат → снятие контроля) и вход в интерфейс.

## Устройство

```
app/
  config.py       настройки из окружения
  tzwindow.py     сутки кабинета и пересчёт в пояс трекера
  rules.py        три правила и их проверка
  models.py       схема данных
  services.py     пороги, постановка адсетов под контроль
  engine.py       движок: тик, выключение, возврат, снятие контроля
  clients/
    keitaro.py    отчёт Admin API
    facebook.py   статусы адсетов через Graph API
  main.py         веб-приложение и вход
  cli.py          консольные команды
```
