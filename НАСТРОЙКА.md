# Настройка с нуля

Пошагово: от пустого сервера до работающего автоконтроля. Пятнадцать шагов,
примерно час, из них большая часть — ожидание, пока Keitaro наберёт статистику.

Всё, что движок показывает, он берёт **из ваших живых кабинетов и вашего
трекера** в момент запроса. Никаких предзаполненных цифр в нём нет.

---

## Шаг 1. Сервер

Нужна любая машина с Python 3.11+, которая работает круглосуточно и может
достучаться до вашей Keitaro и до `graph.facebook.com`. Подойдёт VPS за пару
долларов.

```bash
ssh root@ваш-сервер
apt update && apt install -y python3 python3-pip python3-venv git
```

## Шаг 2. Забрать код

```bash
cd /opt
git clone -b claude/admiring-bohr-tcaj3e https://github.com/ilxtraff/autocontrol_wlt.git
cd autocontrol_wlt
```

## Шаг 3. Установить зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Дальше все команды выполняются с активированным `.venv` — если отключились от
сервера и вернулись, снова сделайте `cd /opt/autocontrol_wlt && source .venv/bin/activate`.

## Шаг 4. Файл настроек

```bash
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте напечатанную строку и впишите её в `.env`:

```bash
nano .env
```

Найдите строку `AC_SECRET_KEY=` и вставьте туда ключ. Остальное пока не трогайте,
но **сразу поставьте безопасный режим** — движок будет всё считать и писать в
журнал, но адсеты не тронет:

```
AC_SECRET_KEY=<вставленный ключ>
AC_DRY_RUN=true
```

Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

## Шаг 5. Первый пользователь

```bash
python -m app.cli createuser admin --role admin
```

Спросит пароль дважды. Роли: `admin` и `ceo` могут менять общие пороги команды,
`buyer` — только свои.

Остальным заведите доступы позже той же командой:

```bash
python -m app.cli createuser sasha --role buyer
```

## Шаг 6. Запустить

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте в браузере `http://ваш-сервер:8000/` — увидите форму входа. Зайдите под
тем логином, который создали на шаге 5.

Пока окно с командой открыто — сервис работает. Как сделать его постоянным, —
шаг 14.

---

## Шаг 7. API-ключ Keitaro

В админке Keitaro: **Настройки → API**. Там лежит ключ (в некоторых версиях
раздел называется иначе или ключ лежит в профиле пользователя — ищите «API key»).
Скопируйте его.

Понадобится ещё адрес трекера — то, что в адресной строке админки, например
`https://tracker.example.com`, без `/admin` на конце.

## Шаг 8. Токен Facebook

Нужен токен с правами `ads_management` и `ads_read`. Правильный вариант для
сервиса — **системный пользователь**, его токен не протухает:

1. [Business Manager](https://business.facebook.com) → **Настройки компании**
2. **Пользователи → Системные пользователи** → *Добавить*
3. Создайте, роль — администратор
4. **Добавить ресурсы** → выберите все рекламные кабинеты, которыми должен
   управлять автоконтроль → доступ **Управление кампаниями**
5. **Создать новый токен** → выберите приложение → отметьте `ads_management`
   и `ads_read` → скопируйте токен

Токен показывается **один раз** — сохраните сразу.

Если у вас уже есть рабочий токен в CRM, можно взять его, но проверьте, что он
долгоживущий: обычный токен из Graph API Explorer умирает через пару часов, и
автоконтроль встанет.

## Шаг 9. Ссылка должна нести ID адсета

Это то, по чему движок сопоставляет адсет в Facebook со строкой в Keitaro.
В ссылке объявления должен быть макрос с ID адсета:

```
https://ваш-домен.com/?sub_id_2={{adset.id}}
```

Facebook сам подставит туда ID. Имя параметра может быть любым из `sub_id_1` …
`sub_id_15` — главное, чтобы то же имя вы указали на шаге 11.

Проверить: откройте в Keitaro **Отчёты**, добавьте группировку по `SubID 2` —
там должны быть числовые ID адсетов, а не пусто.

> Если у вас уже идут заливы через CRM, скорее всего макрос уже стоит —
> просто убедитесь в отчёте, что поле заполнено.

## Шаг 10. Расход должен доезжать до Keitaro

Движок читает расход из колонки `cost` в отчёте Keitaro. Если расход в трекер не
приходит, правила **CPA** и **расход без конверсий** работать не будут — движок
увидит нули и никого не выключит (uCPC тоже, он считается от расхода).

Судя по вашей странице «Расход по адсетам», CRM уже отправляет расход в Keitaro
(колонка «Отправлено»). Убедитесь, что это продолжает работать: в Keitaro в
отчёте по кампаниям колонка **Расход** не должна быть нулевой.

Если расход не приходит — варианты:
* включить в Keitaro встроенную интеграцию с Facebook Ads (она сама тянет спенд);
* продолжать слать расход из CRM через Admin API;
* передавать цену клика прямо в ссылке параметром `cost`.

Это единственный шаг, который делается **не в этом сервисе**, и без него
автоконтроль бесполезен. Не пропускайте его.

## Шаг 11. Подключить Keitaro и токен

В интерфейсе: **Интеграции**.

**Блок «Keitaro»** — заполните и нажмите *Добавить*:

| Поле | Что вводить |
|---|---|
| Название | любое, для себя |
| Адрес | `https://tracker.example.com` |
| API-ключ | из шага 7 |
| Таймзона трекера | `Europe/Moscow` |
| Поле с ID адсета | `sub_id_2` — то же, что в ссылке из шага 9 |

**Блок «Социальные аккаунты Facebook»**:

| Поле | Что вводить |
|---|---|
| Название | имя профиля, для себя |
| FB User ID | можно пропустить |
| Access token | токен из шага 8 |

## Шаг 12. Добавить рекламные кабинеты

Сначала посмотрите, какие кабинеты видит токен:

```bash
python -m app.cli fb-accounts
```

Команда напечатает ID, таймзону и название каждого кабинета. Дальше в интерфейсе,
блок **«Рекламные кабинеты»**, для каждого:

| Поле | Что вводить |
|---|---|
| ID кабинета | число из `fb-accounts`, без `act_` |
| Название | можно пропустить, подтянется |
| Таймзона | **оставьте пустым** — подтянется из Facebook |
| Токен | выберите из списка |
| Keitaro | выберите из списка |

Таймзона тут — самое важное: именно от неё считаются сутки автоконтроля.
Оставьте поле пустым, и сервис возьмёт её из Facebook сам, без опечаток.

## Шаг 13. Проверить связь

```bash
python -m app.cli doctor
```

Команда покажет, отвечает ли Keitaro, жив ли токен, какие сутки сейчас у каждого
кабинета и — главное — **что реально видит Keitaro по вашим адсетам**:

```
== Кабинеты и сутки ==
  [ок]     Кабинет-2: GMT-7 · сейчас 01:31
           сутки 2026-09-14 -> в Europe/Moscow: 2026-09-14 10:00:00 .. 2026-09-14 11:31:37
```

Эта строка и есть ответ на «кабинет американский, а Keitaro московская»: полночь
кабинета — это 10:00 по Москве, и запрос уходит именно от неё.

Не идите дальше, пока `doctor` не скажет «Всё на месте».

## Шаг 14. Пороги

В интерфейсе: **Автоконтроль → Пороги**.

**Общие пороги по гео** — правила команды, их видят все. Добавьте строку на
каждое гео, с которым работаете: гео двумя буквами, затем три числа.

| Поле | Что значит |
|---|---|
| MAX CPA | расход на конверсию, выше которого адсет выключается |
| MAX расход без конв. | сколько адсету позволено потратить, не принеся ни одной конверсии |
| MAX uCPC | расход на уникальный клик |

Пустое поле = правило выключено.

**Мои пороги** — личный список, перебивает общий по этому гео. Заводите только те
гео, где ваши числа отличаются от командных.

> Пороги копируются в адсет в момент постановки под контроль. Правка здесь
> повлияет на новые адсеты, а уже идущие доживут по своим числам.

## Шаг 15. Поставить адсеты под контроль

Примерка — ничего не сохранит, только покажет, что будет:

```bash
python -m app.cli import-adsets --account 1790847419029975 --dry-run
```

Гео определяется по имени: из скобок кампании `[it]` или из куска имени адсета
`..._it_...`. Что не распозналось — будет в списке «не понял гео».

Если всё устраивает, повторите без `--dry-run`:

```bash
python -m app.cli import-adsets --account 1790847419029975
```

Полезные флаги:

* `--geo IT` — задать гео всем сразу, не полагаясь на имена
* `--user sasha` — применить личные пороги этого байера
* `--all` — брать не только активные адсеты

Повторяйте для каждого кабинета. Новые адсеты после заливов ставьте той же
командой — уже стоящие под контролем не задвоятся.

## Шаг 16. Обкатка вхолостую

У вас всё ещё `AC_DRY_RUN=true` — движок считает и пишет решения в журнал, но
адсеты не трогает. Прогоните вручную:

```bash
python -m app.cli tick
```

Откройте **Автоконтроль → Журнал решений**. Посмотрите, что движок хотел бы
сделать. Дайте ему поработать так хотя бы полдня и сверьте с тем, что вы сами
выключили бы руками.

Если выключает слишком рьяно — поднимите пороги. Если не трогает то, что надо
было остановить, — проверьте в `doctor`, доезжают ли расход и уники.

## Шаг 17. Боевой режим

```bash
nano .env
```

Поменяйте `AC_DRY_RUN=true` на `AC_DRY_RUN=false`, сохраните, перезапустите
сервис. С этого момента адсеты выключаются по-настоящему.

## Шаг 18. Сделать постоянным

Чтобы сервис не умирал вместе с ssh-сессией:

```bash
cat > /etc/systemd/system/autocontrol.service <<'EOF'
[Unit]
Description=Автоконтроль адсетов
After=network.target

[Service]
WorkingDirectory=/opt/autocontrol_wlt
ExecStart=/opt/autocontrol_wlt/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now autocontrol
systemctl status autocontrol
```

Логи движка — решения, ошибки, тики:

```bash
journalctl -u autocontrol -f
```

> Сервис отдаёт обычный HTTP. Если он смотрит в интернет, поставьте перед ним
> nginx с сертификатом и включите в `.env` строку `AC_COOKIE_SECURE=true`,
> иначе пароль и кука ходят открытым текстом.

## Если что-то не так

| Что видите | В чём дело |
|---|---|
| `doctor`: Keitaro не отвечает | неверный адрес или API-ключ; проверьте, что сервер вообще достаёт трекер |
| `doctor`: токен мёртв | протух — сделайте системного пользователя по шагу 8 |
| `doctor`: «нет расхода» у всех | расход не доезжает в Keitaro — шаг 10 |
| `doctor`: «нет уников» у всех | в ссылке нет макроса с ID адсета или имя поля не совпадает — шаг 9 |
| Журнал пуст, адсеты `НАБЛЮДАЕТ` | всё в порядке: пороги не превышены |
| В журнале «ошибка» | текст ошибки в колонке «Прим.» — обычно протухший токен |
| Адсет `СНЯТ` | три часа метрики не вернулись; включить может только человек — кнопка «Включить» |

Сменить пароль: `python -m app.cli passwd sasha`.
Список пользователей: `python -m app.cli users`.
